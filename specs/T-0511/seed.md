# T-0511 «Плагин: правила быстрых проверок — конвейер у себя гоняет своё; красный полный прогон возвращает задачу-виновника на доделку»

Описание задачи из трекера как есть (зерна нет: задачу ведёт сессия Claude Code по плану T-0494, решение D-0106 п.3).

Зачем: быстрый CI на PR меняет правила для ботов. Нужно записать, кто и что делает, когда полный прогон по main покраснел, — иначе красное будет висеть ничьим.

Результат:
1. Конвейер у себя гоняет то же, что PR (своё, смоук, названное в зерне), а не полный набор — п.5 take-task ссылается на verify репозитория.
2. Полный прогон красный: Астерион по слияниям после последнего зелёного прогона находит задачу-виновника, возвращает её комментарием «Астерион: доделка — …» (как сверка после слияния). Конвейер, пока полный прогон красный, сначала берёт доделку и не берёт новые задачи с «Меняет базу: да».
3. Перед приёмкой блока Астерион запускает полный прогон кнопкой и принимает блок только по зелёному.
4. Неустойчивый тест в полном прогоне — по правилу «неустойчивый тест» из take-task: один перезапуск, дальше задача на починку.

Где: team-plugin — take-task (п.5, «Запуск по расписанию»), asterion (разделы 3, 4, «По расписанию»).

Кто утверждает: правка asterion — «да» Ерлана; take-task — вердикт Астериона.

Готово, когда: правила записаны и на пробе нарочно сломанный чужой экран вернул задачу-виновника на доделку без участия Ерлана.

Из журнала задачи (решение Ерлана 23.11.2026 по T-0495): PR добавляет к своим экранным тестам файлы из необязательного списка specs/T-xxxx/e2e-also.txt; правило шагу «спека и тесты» заполнять этот список — ввести здесь.

## Что решено при исполнении (можно переиграть, PR не слит)
- Конвейер не может выбрать, какую задачу выдаст трекер, поэтому «не берёт задачи с «Меняет базу: да», пока прогон красный» записано остановкой с новой, седьмой причиной «зелёный полный прогон»: конвейер сам вернётся к задаче, когда отметка позеленеет. Диспетчер трекера должен узнать эту причину — отдельный PR в tl-pm-demo.
- Новая метка Астериона «Астерион: полный прогон красный — …» в журнале задачи-виновника: по ней следующий запуск не разбирает тот же красный прогон заново.
- Номер версии плагина и README не тронуты: поднимаются последним коммитом при слиянии цепочки.
- Правило «как читать отметку» записано один раз — в take-task; asterion ссылается на него.
- Астерион получает право запускать и перезапускать полный прогон по main (и только его): без этого красная отметка могла не позеленеть никогда — конвейер, пока она красная, задачи с базой не берёт, третьего коммита ждать не от кого.
- Тест прежней задачи упал, потому что по зерну виновника поведение должно было измениться: Астерион сам проверяет правку по правилам «правки проверок вне зерна» и пишет её рядом с доделкой.
- Не доказано до слияния: «на пробе сломанный чужой экран вернул виновника на доделку без участия Ерлана» — проба возможна только когда T-0495, T-0503 и этот PR в main.
