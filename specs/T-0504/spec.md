# T-0504 — что проверено и что решено при исполнении

Можно переиграть, PR не слит.

- **Правило трекера «задачи с базой по одной» не мешает** (проверено по коду выдачи очереди в tl-pm-demo, миграция 0047): занятыми считаются только задачи конвейера в статусе «В работе». Припаркованная в «Ожидании» задача места не занимает и «базу» не держит — вторую задачу с базой из другой цепочки трекер выдаст. Править трекер не нужно.
- Обратная сторона того же: вторая задача с базой может начаться, пока PR первой открыт. Поэтому Дедалу велено проверять независимость миграций особо, а конвейер сверяет номер своей миграции перед слиянием (это уже было в п.10 take-task).
- Только линия TradeLab (D-0106 п.2): в ТД+XP порядок пишется как раньше.
- Цепочки не дают права вести две задачи разом: «по умолчанию — ничего» осталось.
- Навык asterion не тронут: проверка техпроекта уже требует «кто пользуется — позже того, кто заводит» и «у каждого объекта один хозяин»; отдельного пункта про цепочки там нет — вопрос Ерлану, добавлять ли (это правка asterion, по его «да»).
- Версия плагина и README не тронуты: последним коммитом при слиянии цепочки.
- Не доказано до слияния: «в техпроекте пробной волны порядок цепочками» и «при остановке конвейер взял задачу другой цепочки» — увидим на первой волне после слияния.
