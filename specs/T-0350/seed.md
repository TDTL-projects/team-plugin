# T-0350 «Плагин tdtl-team: линия разработки ТД+XP (Хугин, Паровоз, Мунин)»

Зерно из трекера, версия задачи 18 (вердикт «Астерион: готово к разработке (версия 18)», 21.11.2026).

## Зачем
Плагин знает одну линию разработки — TradeLab: Дедал / Конвейер / Астерион. Имена участников, метки в журнале, «кто даёт да», кому вопросы и приёмка и с чьего аккаунта GitHub пишут боты зашиты прямо в тексты навыков. Боты ТД+XP (Хугин / Паровоз / Мунин, P-08, репозиторий DocsSystem) по этим текстам будут писать «Конвейер: …» и «Астерион: …», засчитывать вердикты не того участника и звать Ерлана там, где решает Наиль. Нужна вторая линия в тех же навыках, без поломки первой.

## Откуда знаем, что это нужно
- Инструкция «ТДXP-разработка-инструкция-Наилю.md», часть 1 (Ерлан, 19.11): список правок плагина и таблица меток Хугина, Паровоза, Мунина.
- Код плагина (team-plugin, main a4cf346, 0.16.0): «Конвейер» и «Астерион» в метках и правилах `take-task` (10 и 33 раза), `asterion` (3 и 33), `wave`; «засчитывается по автору: участник „Астерион“»; «в GitHub ты пишешь с аккаунта Ерлана»; «Ерлану — push»; вопросы Q-…, приёмка и сводка волны — Ерлану.
- Проверка зерна T-0349 Астерионом 20.11: фильтр `project` никто не включит, если плагин не скажет Мунину и Астериону им пользоваться.

## Кто пользуется и пример
Боты линий и люди в чате. Паровоз на .245 берёт задачу P-08 и пишет «Паровоз: запуск начат», а не «Конвейер: …». Мунин проверяет зерно и пишет «Мунин: готово к разработке (версия 3)»; Паровоз засчитывает это, потому что запись от участника «Мунин». Наиль проверил зерно сам в своём чате — Паровоз засчитывает и его запись. Паровоз встал на вопросе — задача «Ответить на Q-…» уходит Наилю, а не Ерлану. Наиль в чате: «Хугин, допиши для разработки T-04xx» — срабатывает навык Дедала, раздел зерна «Для разработки (Хугин)», репозиторий DocsSystem. Конвейер по задаче P-01 работает ровно как сегодня. Задачу с репозиторием module_dt_check ни один конвейер не ведёт, и PR в нём ни один проверяющий не смотрит и не сливает.

## Готово, когда
1. В `take-task` одна таблица линий: линия → проекты → репозитории → техлид / конвейер / проверяющий → владелец линии → «да» на волну → секреты и боевая база → аккаунт GitHub → кому уведомления проверяющего. Владелец линии — кому вопросы Q-… и задачи «Ответить на Q-…», принимающий задач «Приёмка», шаги приёмки глазами, сводка волны и «что ждёт». TradeLab: все проекты без своего конвейера (T-0349); все репозитории TDTL-projects, кроме репозиториев других линий и вне линий (сейчас это tradelab-app, tl-pm-demo, team-plugin); Дедал / Конвейер / Астерион, владелец Ерлан, «да» Ерлан, секреты Ерлан, GitHub Ерлана, push Ерлану (`PushNotification`). ТД+XP: только P-08 и DocsSystem, Хугин / Паровоз / Мунин, владелец Наиль, «да» Наиль, секреты и боевая база Наиль, GitHub Наиля, сообщение Наилю (`send_message`). Под таблицей — строка «Вне линий: module_dt_check (SP-24), владелец Наиль — задачи с этим репозиторием в «К разработке» не ставят и ни один конвейер их не ведёт, PR не берёт ни один проверяющий; слияние и выкладка — по команде владельца». Остальные навыки ссылаются на неё, а не пересказывают.
2. Линию навык узнаёт из инструкции запуска («кто ты») или по проекту задачи (P-08 → ТД+XP). Метки — те же слова, имя в начале — своей линии («Паровоз: запуск начат», «Мунин: проверка не ослаблена — PR #N»). Вердикт засчитывается по участнику-проверяющему своей линии; в ТД+XP — ещё и по владельцу линии Наилю (его запись с той же меткой, в том числе начинающаяся с «Астерион:», если он проверял в своём чате). Записи участников другой линии не засчитываются. «Ерлан» в правилах линии — владелец линии из таблицы; «да» на секреты и боевую базу — по колонке таблицы. По задачам вне P-08 тексты меток, участники, «да», вопросы и уведомления — как сейчас.
3. Обращения: «Хугин, …» — навык `dedal`, «Паровоз, возьми T-…» — `take-task`, «Мунин, проверь …» — `asterion` (поле `description`).
4. `wave`: в ТД+XP «да» на волну, на секреты и боевую базу — Наиль. `dedal`: раздел «Для разработки (Хугин)» для ТД+XP, DocsSystem в списке репозиториев; `take-task` и `asterion` находят строки «Репозиторий» и «Меняет базу» под обоими заголовками.
5. Каждый бот видит только свою линию. Задачи: Мунин зовёт `find_tasks` с `project: P-08`, Астерион — с `project: -P-08` (зёрна, «конвейер стоит и ждёт»); «кто-то уже ведёт?» в `take-task` ищет по своему конвейеру, а не по «Конвейер». PR: разделы 3, 5 и шаг 2 раздела 6 `asterion` смотрят PR только в репозиториях своей линии из таблицы; репозитории «вне линий» не смотрит никто.
6. Версия 0.17.0 в `plugin.json`, строка в README, одна строка о второй линии в `how-we-work`.

## Решено
- Ерлан, 20.11 (комментарий в T-0349): затишье D-0058 на T-0349 и T-0350 не распространяется — делаем сейчас.
- Наиль, 20.11: уведомления Мунина (то, что Астерион шлёт Ерлану push-уведомлением) — сообщением Ариадны (`send_message`) Наилю в Google Chat. Работает с ключом Мунина и в запуске без окна. Правила Астериона те же: одно сообщение за запуск, только когда есть что сказать, об одном ожидании — один раз (метка «Мунин: Наилю отправлено — …»), в выходные не шлёт (`weekend` не ставит).
- Наиль, 20.11: владелец линии ТД+XP — Наиль, и вся разработка линии (Хугин, Паровоз, Мунин) на нём. Ему вопросы Q-… и задачи «Ответить на Q-…», он принимающий задач «Приёмка», ему шаги приёмки глазами и сводка волны. «Да» на секреты и боевую базу в линии ТД+XP (скрипты, которые Сергей запускает на .248) — тоже Наиль. Паровоз засчитывает вердикты Мунина и записи Наиля под его ключом. Конвейер и Астерион TradeLab в P-08 и DocsSystem не работают.
- Наиль, 20.11: module_dt_check (SP-24, модуль проверки ДТ) — репозиторий Наиля, вне линий, чисто его разработка. Его задачи Наиль ведёт сам, в «К разработке» их не ставят; ни один конвейер их не ведёт, PR не смотрят ни Астерион, ни Мунин; слияние и выкладка на .248 — по команде Наиля, как сейчас.
