## Развилки

1. **Набор дорожек и шум инструментов (п.1).** bpmn.io пишет ссылку на блок и в дорожку, и в её родительскую дорожку. Другой инструмент может писать её только в самую вложенную. Если схему из такого инструмента пересохранят в bpmn.io, каждый блок в поддорожке появится в отчёте правкой вида «дорожки: «L1» → «L», «L1»». **Рекомендую** сравнивать полный набор, как требует зерно. В BRK-TOBE поддорожек нет. Если шум появится — отдельная задача.
2. **Порядок проверок перед сборкой (пп.2–3).** T-0196 `ac1_hardlink` ждёт, что в тексте остановки назван входной файл. Там `-o` — жёсткая ссылка `link.out`, и она уже существует. **Рекомендую** проверять так: сначала совпадение с входными, потом «файл уже есть», потом право записи в папку. Иначе T-0196 покраснеет.
3. **Как проверять право записи (п.2).** Пробный файл не годится: его пришлось бы удалять, а это стоп-список D-0041. **Рекомендую** `os.access(папка, W_OK)`. На Windows `os.access` для папок ненадёжен, но тогда остаётся страховка п.2: отчёт пишется первым, при сбое схемы — «не выкладывать». Оба файла открывать в режиме `"xb"`. Тогда файл, появившийся между проверкой и записью, тоже не затрётся.
4. **`eventDefinitionRef` (п.4).** Зерно называет его атрибутом. В схеме BPMN 2.0 это ребёнок события `<eventDefinitionRef>ED</eventDefinitionRef>`, и тест проверяет именно этот вид. **Рекомендую** учитывать ребёнка. Атрибут учитывать тоже можно, это ничего не стоит.
5. **Ссылки на чертёж (п.4).** `sourceElement`/`targetElement` указывают на id чертежа (`X_di`). Удаление X отказывает, если на любой из его чертежей ссылается элемент, который удаляется не вместе с ним. `sourceRef`/`targetRef`-дети учитываются только внутри `dataInputAssociation`/`dataOutputAssociation`. Удаление их не вычищает (в отличие от `incoming`/`outgoing`), а отказывает.
6. **Подмена записи в тесте (п.2).** Сбой записи схемы тест изображает через `open`/`io.open`/`os.open`. Подходит любая обычная запись: `open`, `ElementTree.write(путь)`, `pathlib`. Схему можно сериализовать в память и до записи отчёта, тест ломает только открытие файла. При сбое записи отчёта текст сообщения тест не проверяет. **Рекомендую** «отчёт не записан, схема не записана».
7. **Корень с другим id (п.5).** Сам корень `Defs_V` тоже попадёт в «Не получилось». **Рекомендую** для него причину вида «у автора другой id корня документа (Defs_V, в исходной Defs) — новое верхнего уровня не добавлено, проверьте, та ли это копия». Тест этого не требует.
8. **SKILL.md (п.3).** Шаг 2: «`-o` и `--report` — только новые файлы: если такой файл уже есть или совпадает с исходной/копией, скрипт остановится». Шаг 5: повторный запуск с `--accept` — под новыми именами (например «…, 2»). Шаг 6, стоп-сигнал: вывод «не выкладывать». Проверяет ревью.
