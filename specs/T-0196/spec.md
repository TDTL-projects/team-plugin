# T-0196 — bpmn-merge: сборка не портит файлы

Идём по зерну (`seed.md`). Трогаем `bpmn_merge.py`, `test_bpmn_merge.py`, `SKILL.md` навыка и `plugin.json`. База не меняется, новой поверхности нет.

## Проверки

Все проверки лежат в `plugins/tdtl-team/skills/bpmn-merge/scripts/test_bpmn_merge.py`. Схемы искусственные, сети нет. Каждая проверка `acN` работает в своей подпапке временной папки. Упавшая проверка не останавливает остальные: в конце печатается список упавших и код выхода 1.

```
python3 -I plugins/tdtl-team/skills/bpmn-merge/scripts/test_bpmn_merge.py
```

## Развилки

1. **Чертёж `_di` при `--accept` (п. 4).**
   - (а) Только когда назван явно.
   - (б) `Task` сам принимает `Task_di`, если у чертежа правка того же автора.
   - (в) Отдельный ключ.

   **Рекомендую (а).** В отчёте чертёж — отдельная строка со своим id в разделе «Положение и цвет», и владелец отвечает по строкам. Вариант (б) возвращает молчаливое «принял больше, чем назвал». Под (а) написан тест. Удаление — исключение: принятое удаление `Task` убирает и его чертёж, иначе останется висячий `bpmnElement` (это требует прежняя проверка N0). В SKILL.md написать: положение принимают по `…_di`; если у стрелки поменялся конец, принимать и её `_di`, иначе линия останется нарисованной к старому блоку.
2. **Чем показать перенос между дорожками (п. 6).**
   - (а) Правкой блока: «дорожка: «Дорожка» → «Дорожка 2»», принимается `--accept B`.
   - (б) Правками дорожек L и L2.

   Тест принимает оба варианта. Но он требует, чтобы новый блок другого автора в той же дорожке не давал конфликта, а при (б) это надо отдельно обходить. **Рекомендую (а):** одна понятная строка на перенос. Два автора перенесли один блок в разные дорожки — это честный конфликт по блоку. При (б) любые две правки одной дорожки дают ложный конфликт.
3. **Ссылки-дети при `--accept` (п. 3, 6).** incoming, outgoing и flowNodeRef не копировать из версии автора целиком, а оставлять то, что уже есть в собранной:
   - у принятой стрелки — перевесить incoming/outgoing со старого конца на новый;
   - у принятого переноса — убрать flowNodeRef из старой дорожки и добавить в новую.

   Тогда ссылки, которые добавили другие авторы или сама сборка, не трогаются.
4. **Порядок принятий (п. 5).** Тест требует, чтобы `--accept ST,SP` (сначала вложенное) удалял оба. Рекомендую сначала применять все принятые правки, потом удаления в порядке `--accept`. Тогда `--accept FG,G` тоже сработает: развилка G теряет `default` правкой, стрелка FG удаляется после неё. Независимость от порядка тест не требует.
5. **Совпадение путей (п. 1).** Сравнивать `os.path.realpath`: файла `-o` ещё может не быть, поэтому `samefile` подходит только как дополнение для существующих файлов. Текст остановки называет файл, тест ищет его имя в выводе. Подходит любой ненулевой код, в том числе `ap.error` → 2.
6. **Запись (п. 2).** Тест подменяет `bm.report`: `main()` должен вызывать `report` как функцию модуля, имя не менять. Рекомендую сначала построить текст отчёта, потом писать оба файла во временные рядом и переносить через `os.replace`. Тогда и сбой самой записи не оставит полуфайла. Тест требует только одно: при сбое отчёта нет новых и изменённых файлов, временных тоже.
7. **Префиксы ns0 (п. 7).** `ET.register_namespace` не принимает префиксы вида `ns\d+`. Рекомендую такие префиксы не регистрировать и для URI BPMN/DI/DC держать привычные `bpmn:`, `bpmndi:`, `dc:`, `di:`. Тест проверяет только, что сборка проходит и результат снова читается.

8. **Членство в дорожках при переносе (ревью, п. 3 и 6).** Принятый перенос даёт Б ровно тот набор дорожек, что у автора: и дорожки, и поддорожки, без повторов. Ссылка на Б снимается со всех дорожек собранной, где Б нет у автора. В том числе с дорожки, которой у автора нет совсем (автор её удалил): иначе Б остаётся в двух дорожках, а удаление пустеющей дорожки отказывает (`ac6_lane_deleted`). Дорожки других авторов этим не задеваются: новая дорожка приходит без ссылок на старые блоки, поэтому Б в ней быть не может. Ссылки других блоков не трогаются. Новая дорожка вставляется без ссылок на блоки, которые уже были в исходной: перенос существующего блока — правка этого блока, без решения она не применяется. Ссылки на новые блоки в новой дорожке остаются.
9. **Что считать частью элемента (ревью, п. 5).** Рекомендую так: часть — это `…EventDefinition`, `ioSpecification` со всем содержимым, `property`, `…LoopCharacteristics`. Части удаляются вместе с элементом. Вложенные блоки, события, стрелки, `laneSet`/`childLaneSet` и всё, на что ссылаются снаружи, — по-прежнему причина отказа.
10. **Дорожки нет в собранной (ревью, п. 6).** Новой дорожки нет в собранной, или под её id лежит не дорожка, или дорожка под конфликтом. Дорожка под конфликтом — это и «два автора добавили разный элемент с одним id», когда оба — дорожки (`ac6_lane_conflict`), при любом порядке авторов. Тогда правка блока не применяется целиком: ни имя, ни дорожка. Правка стоит только в «Не получилось». Проверку делать до изменения элемента, а не после.
11. **Чертёж (ревью, п. 5).** Отказ, если на элемент ссылается `bpmnElement` у `BPMNPlane` (или у `BPMNDiagram`). Иначе принятое удаление снесёт весь чертёж вместе с чертежами всех блоков. `categoryValueRef` у группы — тоже ссылка, которая держит элемент. У детей-шумов bpmn.io `categoryValueRef` такой силы нет: на них правило не распространяется.
12. **Пути `-o`/`--report` (ревью, п. 1).** До сборки проверить: папка существует; путь — не папка; путь не совпадает со входным файлом ни по `realpath`, ни по `os.path.samefile`. Последнее ловит жёсткую ссылку. Путь с косой чертой в конце (`/` или `os.sep`) — это папка, а не файл: стоп, даже если такой папки нет. `abspath` срезает черту, поэтому проверка папки её не видит. Иначе остановиться через `ap.error` и назвать путь. Папку не создавать.
13. **Одинаковый новый блок в разных дорожках (ревью 2, п. 6).**
   - (а) Блок остаётся в дорожке первого автора. Новая дорожка второго автора приходит без ссылки на блок, который уже добавил другой автор.
   - (б) Конфликт по блоку.

   **Рекомендую (а).** Блоки одинаковые, по правилу сборки это не конфликт. Цена: отчёт молчит о том, что второй автор положил блок в другую дорожку. Если владельцу это понадобится, это отдельная задача. Ссылки новой дорожки на её собственные новые блоки остаются (развилка 8).
14. **Повтор id в `--accept` (ревью 2, п. 4).** Рекомендую убирать повторы, сохраняя порядок, и ничего не писать в «Не получилось»: это не ошибка владельца. Тест требует только одну строку в «Принято».

СТОП нет.
