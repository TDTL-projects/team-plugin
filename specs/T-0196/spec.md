## Развилки

1. **Чертёж `_di` при `--accept` (п. 4).**
   - (а) Только когда назван явно.
   - (б) `Task` сам принимает `Task_di`, если у чертежа правка того же автора.
   - (в) Отдельный ключ.

   **Рекомендую (а).** В отчёте чертёж — отдельная строка со своим id в разделе «Положение и цвет», и владелец отвечает по строкам. Вариант (б) возвращает молчаливое «принял больше, чем назвал». Под (а) написан тест. Удаление — исключение: принятое удаление `Task` убирает и его чертёж, иначе останется висячий `bpmnElement` (это требует прежняя проверка N0). В SKILL.md написать: положение принимают по `…_di`; если у стрелки поменялся конец, принимать и её `_di`, иначе линия останется нарисованной к старому блоку.
2. **Чем показать перенос между дорожками (п. 6).**
   - (а) Правкой блока: «дорожка: «Дорожка» → «Дорожка 2»», принимается `--accept B`.
   - (б) Правками дорожек L и L2.

   Тест принимает оба варианта. Но он требует, чтобы новый блок другого автора в той же дорожке не давал конфликта, а при (б) это надо отдельно обходить. **Рекомендую (а):** одна понятная строка на перенос. Два автора перенесли один блок в разные дорожки — это честный конфликт по блоку. При (б) любые две правки одной дорожки дают ложный конфликт.
3. **Ссылки-дети при `--accept` (п. 3, 6).** incoming, outgoing и flowNodeRef не копировать из версии автора целиком, а оставлять то, что уже есть в собранной:
   - у принятой стрелки — перевесить incoming/outgoing со старого конца на новый;
   - у принятого переноса — убрать flowNodeRef из старой дорожки и добавить в новую.

   Тогда ссылки, которые добавили другие авторы или сама сборка, не трогаются.
4. **Порядок принятий (п. 5).** Тест требует, чтобы `--accept ST,SP` (сначала вложенное) удалял оба. Рекомендую сначала применять все принятые правки, потом удаления в порядке `--accept`. Тогда `--accept FG,G` тоже сработает: развилка G теряет `default` правкой, стрелка FG удаляется после неё. Независимость от порядка тест не требует.
5. **Совпадение путей (п. 1).** Сравнивать `os.path.realpath`: файла `-o` ещё может не быть, поэтому `samefile` подходит только как дополнение для существующих файлов. Текст остановки называет файл, тест ищет его имя в выводе. Подходит любой ненулевой код, в том числе `ap.error` → 2.
6. **Запись (п. 2).** Тест подменяет `bm.report`: `main()` должен вызывать `report` как функцию модуля, имя не менять. Рекомендую сначала построить текст отчёта, потом писать оба файла во временные рядом и переносить через `os.replace`. Тогда и сбой самой записи не оставит полуфайла. Тест требует только одно: при сбое отчёта нет новых и изменённых файлов, временных тоже.
7. **Префиксы ns0 (п. 7).** `ET.register_namespace` не принимает префиксы вида `ns\d+`. Рекомендую такие префиксы не регистрировать и для URI BPMN/DI/DC держать привычные `bpmn:`, `bpmndi:`, `dc:`, `di:`. Тест проверяет только, что сборка проходит и результат снова читается.
