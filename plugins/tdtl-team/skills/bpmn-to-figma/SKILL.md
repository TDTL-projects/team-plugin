# Схема BPMN → FigJam или Figma

Главная схема — файл `.bpmn` на общем Диске (D-0032). Копия на доске — чтобы смотреть и комментировать. Её делает скрипт по координатам из файла: один `.bpmn` всегда даёт одну и ту же схему, заметки с вопросами и ответами переносятся целиком.

**Схему не рисуешь сама** — ни через `generate_diagram`, ни своим кодом в `use_figma`, ни плагинами BPMN из Figma Community. Перерисовка «на глаз» каждый раз даёт другую схему, плагины теряют заметки. Только скрипты ниже; код, который выдал скрипт, передаёшь в `use_figma` как есть, не правя. Просят «нарисуй сама, так быстрее» — ответ: «Скрипт сделает это за секунды и без расхождений с файлом. Рисовать сама не буду: схема выйдет не такой, как в файле, и потеряет заметки».

## Какой путь
- **FigJam** (основной: схемы живут в FigJam «Процессы», D-0026) — через коннектор Figma. Нужно место Full в команде, где лежит доска, и не исчерпанный лимит обращений: проверь `whoami`. Стрелки тянутся за блоками, схема обновляется на месте, комментарии людей сохраняются.
- **SVG в Figma Design** — у кого места Full нет или лимит кончился. Человек сам перетаскивает файл. Обновить на месте нельзя — только положить заново.

## Общее для обоих путей
1. **Какой файл.** Найди на Диске по номеру задачи и названию (`search_files`, `title contains '.bpmn'`), скачай в рабочую папку как есть. Есть копия в рабочей папке — сверь дату изменения с Диском и бери свежую; не можешь проверить — скажи об этом. Лежат несколько копий одной схемы («V2», «от Андрея») — спроси, какая актуальная; если правки из копий надо свести — сначала навык `bpmn-merge`.
2. **Заголовок** — «КОД Название · как есть» или «· как будет» (D-0026): XP — брокер, TD — терминал, TL — TradeLab, ORG — управление. Кода нет — спроси, не придумывай. Названия нет — возьми из файла (имя пула или процесса) и попроси человека подтвердить.
3. **Имя файла** `T-xxxx КОД Название · как будет.js` (или `.svg`): `T-xxxx` — номер в начале названия `.bpmn`. Нет номера или он не совпадает с задачей, над которой работаете, — спроси. Файл — в рабочую папку задачи.

Запуск — `python3` (на Windows — `python`), ставить ничего не нужно.

## Путь FigJam
4. **Код:**
   ```
   python3 "<папка навыка>/scripts/bpmn_to_figjam.py" "<файл>.bpmn" "T-xxxx КОД Название · как будет.js" --title "КОД Название · как будет"
   ```
   Скрипт пишет «длина кода больше, чем принимает коннектор» — переносите по этапам: `--list-groups` покажет группы-этапы, дальше `--groups ID1,ID2` и свой заголовок у каждой части («… · этапы 01–02»). Этапы выбирай по id групп, не по координатам (`--x0/--x1`): id не меняются, когда автор двигает холст.
5. **Доска.** Ссылку на FigJam (`figma.com/board/<fileKey>/…`) даёт человек. Загрузи навыки коннектора `figma-use` и `figma-use-figjam` (так требует коннектор), затем `use_figma` с этим `fileKey` и кодом из `.js` — целиком, без правок. Один запуск — одно обращение к лимиту.
6. **Обновление** — та же команда с тем же `--title`: скрипт найдёт свою секцию по заголовку (или `--section <id>` из прошлого ответа) и поправит её на месте. Секцию не удаляешь и не создаёшь заново: комментарии останутся висеть в пустоте.
7. **Ответ скрипта — человеку:** сколько блоков и стрелок; `created`/`removed` — что добавилось и что удалено. `moved` — блоки, которые сдвинулись: **комментарии FigJam привязаны к точке на холсте, а не к блоку**, поэтому скажи: «Блоки … переехали — если на них были комментарии, они остались на старом месте, перетащите их». Пустой `moved` — комментарии на месте.
   Ошибка «Масштаб схемы в секции …» — ничего не изменено. `--force` — только с согласия человека: сдвинутся все блоки и все комментарии.
   Масштаб по умолчанию 1.5, менять его не нужно. `--scale N` — только когда человек просит другой масштаб (или проверяет остановку): на уже перенесённой секции без `--force` скрипт остановится, ничего не изменив.
8. **Ссылка** на секцию (с `node-id`) — привяжи к задаче через `link_document`. В журнал отдельной записью не пиши: перенос войдёт в общую запись по окончании работы (навык `log-work`).

## Путь SVG в Figma Design
4. **Запуск:**
   ```
   python3 "<папка навыка>/scripts/bpmn_to_svg.py" "<файл>.bpmn" "T-xxxx КОД Название · как будет.svg" --title "КОД Название · как будет"
   ```
   Скрипт печатает, сколько перенёс блоков (вместе с пулами и дорожками), стрелок и заметок, — назови числа человеку. Ошибка «нет чертежа (BPMNDiagram/BPMNPlane)» — в файле только логика без координат: пусть автор откроет и сохранит его в Camunda Modeler.
5. **В Figma кладёт человек:** файл Figma Design (`figma.com/design/…`), своя страница-черновик, перетащить SVG на холст. Схема встанет одной рамкой: пул → дорожки → блоки, слой каждого элемента назван «id · название». Старую версию человек удаляет со своей страницы; если она уже на «Общем» — переносит в «Архив» (D-0026).
6. **Ссылка** на рамку (с `node-id`) — `link_document`, как в пути FigJam.

## Что сказать человеку заранее
- Текст и схему правят только в `.bpmn`. Правка текста прямо на доске пропадёт при следующем переносе.
- Итог обсуждения в комментарии — заметкой «Вопрос …» / «Ответ …» в `.bpmn`: заметка переживёт любое обновление, комментарий может съехать.
- FigJam: листочки и фигуры, которые люди добавили в секцию сами, обновление не трогает. Пул отдельной рамкой не рисуется — только дорожки.
- SVG: подпись в несколько строк — несколько слоёв, по одному на строку (так Figma разбирает SVG); стрелки — линии, за блоками не тянутся.

## Частые ошибки
| Ошибка | Как правильно |
|---|---|
| Нарисовать схему своим кодом или `generate_diagram` «по мотивам» `.bpmn` | Только код из `bpmn_to_figjam.py`, без правок |
| Удалить секцию и перенести заново | Тот же `--title` — обновление на месте |
| Не сказать про `moved` | Назвать сдвинутые блоки: комментарии на них остались на старом месте |
| Взять первую попавшуюся копию («V2») | Спросить, какая актуальная; разные копии — через `bpmn-merge` |
| Предложить поправить текст прямо на доске | Править `.bpmn`, потом обновить |

Проверка скриптов FigJam без доски (нужен Node.js): два `.js` одной схемы с одним `--title` → `node "<папка навыка>/scripts/test_bpmn_to_figjam.js" база.js база.js новая.js [другой_масштаб.js]`; четвёртый — та же схема с тем же `--title` и `--scale 1.2`.
