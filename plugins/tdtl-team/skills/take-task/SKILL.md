# Провести задачу до слияния

Работаешь в репозитории продукта. Правила репозитория (`CLAUDE.md`, `.claude/`) главнее этого навыка: там проверки, стоп-список и демо именно этого репозитория. Слияние после проверок делает исполнитель сам; стоп-список — только по «да» Ерлана.

**Роли (D-0054).** Тот, кто ведёт задачу по этому навыку, — **конвейер**: запуск по расписанию, человек в Claude Code или агент в чате. Спека, тесты, код, ревьюер и PR — его шаги, в журнале он пишет от имени «Конвейер». **Дедал** — не шаг конвейера: он решает до разработки, готово ли зерно (навык `dedal`), и принимает после (навык `review-pr`).

**Одна сессия — одна задача.** Память между сессиями — журнал задачи: после каждого шага запись «что сделано, что дальше», чтобы следующая сессия продолжила с этого места, а не с начала.

## Метки в журнале
По этим фразам запуски и Дедал понимают друг друга. Пиши их дословно, с начала записи; других слов для того же не придумывай.

| Метка | Кто пишет | Что значит |
|---|---|---|
| «Конвейер: запуск начат» | исполнитель, сразу как взял задачу | задачу ведут: зерно, статус, ветку и PR не трогать |
| «Конвейер: запуск закончен: …» | исполнитель, когда закончил работу над задачей в этой сессии | можно смотреть |
| «Ревьюер: …» | исполнитель, после последнего круга ревью | что нашли, что исправлено, что отложено и почему |
| «Дедал: нужны правки в PR #N — …» | Дедал, журнал задачи и PR | причина ожидания снята — исправляй |
| «Дедал: доделка — …» | Дедал, комментарий задачи | задача вернулась в «В работе» после слияния |
| «да» | Ерлан, комментарий задачи или PR | слияние стоп-списка разрешено |

## 1. Взять
- Конкретную: `take_for_dev T-…`. Следующую по очереди: `take_next_for_dev` с направлением (TL — TradeLab, ORG — трекер и плагин). Очередь, лимит «не больше 2 в работе» и «задачи с базой по одной» решает трекер — не обходи их.
- Не взялось — скажи почему (ответ трекера) и закончи.
- Сразу запись в журнал (`add_worklog`): «Конвейер: запуск начат. Идёт разработка: пока в журнале нет записи «Конвейер: запуск закончен», не меняйте зерно, статус, зависимости и вопросы этой задачи, ветку claude/T-xxxx-… и её PR». Ведёшь не по расписанию — допиши в скобках, кто: «(вручную: Claude Code у Наиля)», «(вручную: чат Ерлана)». В ссылках — эта сессия, если её адрес известен. Без этой записи Дедал примет твой PR за чужой и может слить его посреди правок.
- Репозиторий задачи — строка «Репозиторий» в разделе зерна «Для разработки (Дедал)». Открыт не он — подключи нужный (`add_repo`, клон). Нет доступа — «Остановка», не обходи.

## 2. Ветка, зерно, факты
- От свежего `main`: `claude/T-xxxx-коротко`. Номер задачи в имени ветки и в названии PR обязателен — по нему трекер двигает статус.
- Зерно — в `specs/T-xxxx/seed.md` как есть.
- **Факты.** У шага «спека и тесты» нет доступа к трекеру и базе. Зерно опирается на то, чего нет в коде (что отвечает инструмент трекера, сколько записей такого вида в базе, как выглядит запись), — выгрузи это в `specs/T-xxxx/data.md`: коротко, без данных клиентов и личных почт. Зерну хватает кода — файл не нужен.
- **Доделка.** Задача вернулась в «В работе» с комментарием «Дедал: доделка — …» или её вернул человек (по ней уже был слитый PR) — прочитай комментарии в `get_task`: работа — то, что в них просят, в рамках зерна. Ветка новая: `claude/T-xxxx-доделка`.

## 3. Спека и тесты до кода
Запусти агента `spec-tests` (до версии 0.14 он назывался `dedal`). Он пишет спеку (или «идём по зерну»), приёмочные тесты и замок `specs/T-xxxx/tests.lock`.
- Ответил `СТОП` → раздел «Остановка».
- Иначе — коммит «T-xxxx Спека и тесты» и push ветки. PR пока не открывай: CI запускается на PR, а тесты ещё красные.
- Журнал: «Конвейер: спека и тесты — что затрагивает, меняет ли базу, какие тесты».

## 4. Код
- Пиши, пока тесты под замком не станут зелёными. **Файлы из `tests.lock` не правь** — хук не даст, а где хука нет, сверит ревьюер. Кажется, что тест неверен или задача невыполнима — не обходи: «Остановка».
- Рамка — спека или зерно. Видишь лучший путь — одна строка в «Развилки», делай как написано.

## 5. Проверки у себя
Всё, что требует репозиторий (навык `verify` или `CLAUDE.md`), включая базу, если её можно поднять. Красное — чини; три попытки не помогли — «Остановка».

**Неустойчивый тест.** Тест упал, а при повторе прошёл без правок — это не «прошло». Один перезапуск можно; дальше — запись в журнал с названием теста, строка «неустойчивый тест: …» в описании PR и задача на починку (нет такой — заведи, навык `new-task`). Второй раз подряд молча не перезапускай.

## 6. Ревьюер
Агент `reviewer` на дифф. Блокирует — чини и запусти ещё раз; после двух кругов блокеры остались — «Остановка».
- Журнал, одной записью после последнего круга: «Ревьюер: блокеры — …; исправлено — …; отложено — … (почему)». Нет находок — «Ревьюер: находок нет». Отложенное без причины не оставляй. По этой записи Дедал после слияния видит, что ты отбросил.
- **Урок.** Ревьюер нашёл блокер, который не поймал ни один тест под замком, — допиши строку в `specs/LESSONS.md` репозитория: что за случай, одной фразой, без истории задачи («имена, которые кончаются на «ь»», «две сессии пишут одновременно»). Файла нет — создай. Не больше 30 строк: похожие случаи объединяй. Шаг «спека и тесты» читает этот файл перед следующей задачей.

## 7. PR и CI
- Подтяни `main` (`git fetch origin main && git merge origin/main`), снова проверки из п.5, если что-то пришло.
- Открой PR в `main`: «T-xxxx Название задачи». В описании по-русски: что сделано; демо «открыть → нажать → увидеть»; что проверено и чем; развилки; меняет ли базу. Трекер сам поставит «На проверке».
- Дождись CI. Красный — почини в той же ветке; два круга не помогли — «Остановка».
- Правишь уже открытый PR по замечаниям — поставь первой строкой его описания «НЕ СЛИВАТЬ: идут правки» и убери, когда закончил.

## 8. Демо на preview
По навыку репозитория `demo` или его `CLAUDE.md`: сам пройди шаги демо на preview. Непроверенное в демо не пиши. Шаг, который требует человека (например, код из письма), так и помечай: «проверит Ерлан».

## 9. Стоп-список
Перед слиянием проверь, не попало ли в PR то, что сливается только по «да» Ерлана. Список — у репозитория: `scripts/stop-list.sh` (запусти его) и `CLAUDE.md`. Нашёл — «Остановка», причина: «да Ерлана на слияние», и простыми словами, что именно в PR из списка. Вопрос Q-… для этого не заводи: ответ Ерлану готовит Дедал.

## 10. Слияние
- Прямо перед слиянием ещё раз подтяни `main` и сверь то, за что спорят параллельные PR: номер версии (запись в списке изменений) и номер миграции — следующие после `main`. Разошлись — поправь последним коммитом и дождись CI.
- `gh api -X PUT repos/<владелец>/<репо>/pulls/<N>/merge -f merge_method=squash`. GitHub сам не сольёт без зелёного CI.
- Ответ «ветка отстала» — `gh api -X PUT repos/<владелец>/<репо>/pulls/<N>/update-branch`, дождись CI, слей.
- Трекер сам поставит «Готово». Репозиторий выкатывает сам при слиянии — проверь, что выкатка прошла (как — в его `CLAUDE.md`).
- Журнал: «Конвейер: запуск закончен: что сделано, ссылка на PR, демо».
- После слияния Дедал сверяет сделанное с зерном (навык `review-pr`). Нашёл расхождение — задача вернётся в «В работе» с комментарием «Дедал: доделка».

## Остановка
Не проталкивай через блокер — паркуй задачу и бери следующую.
1. Журнал: что мешает и какой ответ нужен, ссылка на ветку или PR.
2. Нужен ответ человека — вопрос `add_note` (вопрос, к задаче) и задача «Ответить на Q-…» тому, кто отвечает (обычно Ерлан), со сроком через неделю (D-0027). Для «да Ерлана на слияние» вопрос не нужен.
3. Задача — в «Ожидание», в «чего ждём» — номер вопроса или «да Ерлана на слияние».
4. Журнал: «Конвейер: запуск закончен: остановка — …».
5. Вернуться можно, когда вопрос закрыт ответом, Ерлан написал в комментарии задачи «да» после записи об остановке, или Дедал после остановки оставил «Дедал: нужны правки» — тогда исправь то, что он написал, в той же ветке и снова пройди п.5–9. PR слил Дедал — задача уже закрыта, ничего не делай.

## Запуск по расписанию
Для запланированной задачи «Конвейер». Ключ трекера, репозитории, направления и сколько задач брать за запуск — в её инструкции; всё остальное — здесь.
1. **Выбор задачи**, по порядку:
   - `find_tasks`: ответственный «Конвейер», статус «В работе». По каждой `get_task`: после последней записи «Конвейер: запуск начат» нет «Конвейер: запуск закончен» и ей меньше 90 минут — задачу ведёт другой запуск, пропусти. Первую свободную продолжай с места, где остановились (ветка, PR, журнал, спека). Есть комментарий «Дедал: доделка» новее последнего слитого PR — это доделка (п.2 выше).
   - Иначе — ответственный «Конвейер», статус «Ожидание». Причина снята (п.5 «Остановки») — верни в «В работе» (`update_task`) и продолжай.
   - Иначе — `take_next_for_dev` по направлениям из инструкции запуска, в её порядке. Брать нечего — закончи одной строкой с причиной из ответа трекера.
2. **Оценка сложности [ОЦЕНКА]** — до спеки. Задача сложная, если верно хоть одно: в зерне «Меняет базу: да»; задевает стоп-список; новый экран или путь пользователя от начала до конца; по зерну больше 5 файлов или несколько модулей; вход, доступы, документы клиентов; прошлый запуск по ней остановился из-за красных проверок. Сомневаешься — сложная. Для сложной шаги «спека и тесты», код и ревьюер запускай на старшей модели из инструкции запуска. Журнал одной строкой: «Оценка сложности [ОЦЕНКА]: простая|сложная — почему; модель — …».
3. Дальше — пп. 1–10 этого навыка. «К разработке» и «Готово» задачам не ставишь: это админ и трекер.

Не пишем в трекер данные клиентов: номера ДТ, договоров, счетов, суммы, чужие почты.
