# Провести задачу до слияния

Работаешь в репозитории продукта. Правила репозитория (`CLAUDE.md`, `.claude/`) главнее этого навыка. Слияние после проверок делает исполнитель сам; стоп-список — только по «да» Ерлана (решение о конвейере, 04.11.2026).

## 1. Взять
- Конкретную: `take_for_dev T-…`. Следующую по очереди: `take_next_for_dev` с направлением (TL — TradeLab). Очередь, лимит «не больше 2 в работе» и «задачи с базой по одной» решает трекер — не обходи их.
- Не взялось — скажи почему (ответ трекера) и закончи.

## 2. Ветка и зерно
- От свежего `main`: `claude/T-xxxx-коротко`. Номер задачи в имени ветки и в названии PR обязателен — по нему трекер двигает статус.
- Зерно — в `specs/T-xxxx/seed.md` как есть.
- Задачу вернули на доделку (по ней уже был слитый PR) — прочитай комментарии в `get_task`: работа — то, что в них просят, в рамках зерна.

## 3. Дедал — спека и тесты до кода
Запусти агента `dedal`. Он пишет спеку (или «идём по зерну»), приёмочные тесты и замок `specs/T-xxxx/tests.lock`.
- Ответил `СТОП` → раздел «Остановка».
- Иначе — коммит «T-xxxx Спека и тесты» и push ветки. PR пока не открывай: CI запускается на PR, а тесты ещё красные.
- Журнал: `add_worklog` — что затрагивает, меняет ли базу, какие тесты.

## 4. Код
- Пиши, пока тесты Дедала не станут зелёными. **Файлы из `tests.lock` не правь** — хук не даст. Кажется, что тест неверен или задача невыполнима — не обходи: «Остановка».
- Рамка — спека или зерно. Видишь лучший путь — одна строка в «Развилки», делай как написано.

## 5. Проверки у себя
Всё, что требует репозиторий (навык `verify` или `CLAUDE.md`), включая базу, если её можно поднять. Красное — чини; три попытки не помогли — «Остановка».

## 6. Ревьюер
Агент `reviewer` на дифф. Блокирует — чини и запусти ещё раз; после двух кругов блокеры остались — «Остановка».
- Журнал (`add_worklog`), одной записью после последнего круга: «Ревьюер: блокеры — …; исправлено — …; отложено — … (почему)». Нет находок — «Ревьюер: находок нет». Отложенное без причины не оставляй. По этой записи Дедал после слияния видит, что ты отбросил (D-0045).

## 7. PR и CI
- Подтяни `main` (`git fetch origin main && git merge origin/main`), снова проверки из п.5, если что-то пришло.
- Открой PR в `main`: «T-xxxx Название задачи». В описании по-русски: что сделано; демо «открыть → нажать → увидеть»; что проверено и чем; развилки; меняет ли базу. Трекер сам поставит «На проверке».
- Дождись CI. Красный — почини в той же ветке; два круга не помогли — «Остановка».

## 8. Демо на preview
По навыку репозитория `demo`: сам пройди шаги демо на preview. Непроверенное в демо не пиши. Шаг, который требует человека (например, код из письма), так и помечай: «проверит Ерлан».

## 9. Стоп-список
Перед слиянием проверь, не попало ли в PR то, что сливается только по «да» Ерлана: миграции рабочей базы, серверные функции, секреты, правки самих проверок (CI, `.claude/settings.json`, хуки, замки тестов). В репозитории для этого есть `scripts/stop-list.sh` — запусти его. Нашёл — «Остановка», причина: «жду «да» на слияние», и простыми словами что именно в PR из списка.

## 10. Слияние
- `gh api -X PUT repos/<владелец>/<репо>/pulls/<N>/merge -f merge_method=squash`. GitHub сам не сольёт без зелёного CI.
- Ответ «ветка отстала» — `gh api -X PUT repos/<владелец>/<репо>/pulls/<N>/update-branch`, дождись CI, слей.
- Трекер сам поставит «Готово». Журнал: что сделано, ссылка на PR, демо.
- Чужие PR (другого разработчика) проверяет и сливает Дедал по навыку `review-pr` (D-0041). Твои PR, ждущие «да», Дедал смотрит каждый час: простое из стоп-списка сливает сам, остальное готовит Ерлану; слитое проверяет после слияния (D-0045).

## Остановка
Не проталкивай через блокер — паркуй задачу и бери следующую.
1. Журнал: что мешает и какой ответ нужен, ссылка на ветку или PR.
2. Нужен ответ человека — вопрос `add_note` (вопрос, к задаче) и задача «Ответить на Q-…» тому, кто отвечает (обычно Ерлан), со сроком через неделю (D-0027).
3. Задача — в «Ожидание», в «чего ждём» — номер вопроса или «да Ерлана на слияние».
4. Вернуться можно, когда вопрос закрыт ответом, Ерлан написал в комментарии задачи «да» после записи об остановке, или Дедал после остановки оставил в PR «Дедал: нужны правки» — тогда исправь то, что он написал, в той же ветке и снова пройди п.5–9 (D-0045). PR слил Дедал — задача уже закрыта, ничего не делай.

Не пишем в трекер данные клиентов: номера ДТ, договоров, счетов, суммы, чужие почты.
