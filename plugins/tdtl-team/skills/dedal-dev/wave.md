# Режим «волна» (D-0120 п.1, п.4–6)

Группа связанных задач: общие таблицы, экраны или файлы (три задачи и больше или хоть одна общая таблица либо экран — волна). Техпроект, зёрна, ветка волны `wave/<N>`, маленькие PR в неё, в конце — полный прогон, тестировщик, сверка проверяющего и **один PR в `main`**.

Первоисточники до уборки (T-0781) — действующие навыки; здесь только то, что меняется:
- подготовка, шаги Архонта — `wave/SKILL.md`, шаги 1–7 (линия TradeLab);
- техпроект, «Для разработки (Дедал)», уроки, связи — `dedal/SKILL.md`, разделы «Техпроект волны», «Раздел «Для разработки (Дедал)»» (короткий вид для задачи волны TradeLab), «Карта сторожей и уроки», «Связи и порядок»;
- проверка техпроекта и зёрен — `asterion/1-tech-and-seeds.md`, «Техпроект до зёрен» и «Зёрна перед «К разработке»»;
- правки проверок — `asterion/2-checks-in-pr.md`; сверка — `asterion/3-after-merge.md`; приёмка — `asterion/4-acceptance.md`;
- шаги разработки задачи — `take-task/steps.md` и `task.md` рядом.

Дирижёр не нужен: ход ведёшь ты, Архонта и проверяющего зовёшь субагентами (как звать — `conductor`, «Как запускать роль»; Архонт пишет своим подключением, не «Астерион»; ключи — основа).

## Подготовка — до «да» Ерлана
Три независимых взгляда, как в `task.md`: постановка (Архонт), техпроект (ты), проверка (проверяющий).

**1. Рамка и документы** — Архонт, `wave/SKILL.md` шаги 1–2. «Да» Ерлана на рамку и вопросы пачкой — по `wave` (это не «да» на волну).

**2. Техпроект — ты.** По `dedal/SKILL.md`, «Техпроект волны», с одним отличием: **файл на раздел**, а не один документ. Папка `docs/waves/<номер задачи плана>-wave-<N>/`: `README.md` — оглавление и номера разделов, дальше файл на раздел с тем же номером (`2-objects.md`, `3-access.md`, `7-order.md` …). Строка «Техпроект» в зерне называет файлы и строки. Номера задачи в названии PR и ветки нет. Запись «Дедал: самопроверка — …» по вопросам того же раздела.

**3. Проверка техпроекта** — `dev-checker`: «Проверь техпроект волны N: папка …, PR #N, коммит …. Правила — `asterion/1-tech-and-seeds.md`, «Техпроект до зёрен»». Вердикт — его запись в журнале задачи плана. После «Астерион: техпроект проверен — PR #N (коммит …)» PR техпроекта сливаешь ты; коммит новее проверенного — снова проверяющий.

**4. Зёрна** — Архонт, `wave/SKILL.md` шаг 4; «Для разработки (Дедал)» — ты, короткий вид. Каждой задаче — `set_dev`: режим «волна», зона, сложность. Связи «зависит от» — по разделу порядка техпроекта.

**5. Приёмка блока** — Архонт, `wave/SKILL.md` шаг 5.

**6. Проверка пачки** — `dev-checker` с чистого листа: «Проверь волну N: T-…, T-…; техпроект — папка …. Правила — `asterion/1-tech-and-seeds.md`, «Зёрна перед «К разработке»»». Вердикты — по задаче, вида «вердикт», «Астерион: готово к разработке (версия N)»: на эту метку смотрит трекер, когда ставит «К разработке» по «да».

**7. Одно «да»** — сводка Ерлану по `wave/SKILL.md` шаг 7. «Да» — комментарий Ерлана в узле волны, начатый словом «да»; трекер сам ставит «К разработке». Ждёшь — остановка на узле по основе («Конец запуска»). Уроки — по `dedal`, один PR на волну.

## Ветка волны
**Пока трекер считает «Готово» любой слитый PR** (T-0778, п.2) — по новому порядку волну не начинаешь: PR в ветку волны закроет задачу раньше времени. Остановка «ждём T-0778».

**8. Ветка** `wave/<N>` от свежего `main`, push. Защита `main` не ослабляется; в `main` без PR никто не пишет.

**9. Задача волны — маленький PR в ветку волны.** По `task.md`, шаги 4–14, с отличиями:
- ветка задачи `claude/T-xxxx-…` от `wave/<N>`, PR — в `wave/<N>`;
- CI лёгкий (идёт на любой PR); слияние — после ревьюера и зелёного CI, сам;
- **правки проверок** — без вердикта на каждый PR: запись «правка проверок вне зерна» и строка в описании PR, как обычно. Вердикт проверяющего — **один на цепочку**, когда её задачи слиты: «Стала ли проверка слабее в цепочке … ветки `wave/<N>` — коммиты от … до …? Правила — `asterion/2-checks-in-pr.md`». «Проверка ослаблена» — правка новым PR в ветку волны, затем снова проверяющий на эту правку;
- тестировщик и сверка — не на каждую задачу, а в конце волны (п.12);
- секреты, боевая база, база и функции трекера — «да» Ерлана, как в `task.md`, п.11.

**10. Срочная правка во время волны** идёт в `main` своим режимом (быстрый или задача). Потом ветка волны подтягивает `main`: PR «Волна N: подтянуть main» из `main` в `wave/<N>` способом merge (не squash), лёгкий CI, слияние. Конфликт — разбирает исполнитель, потом ревьюер на разрешение.

## Параллельно
- Старт — с двух потоков. Поток — одна цепочка техпроекта; второй поток — второй исполнитель в отдельном рабочем каталоге (`git worktree`) в этой же сессии; диспетчер вторую сессию не пускает (T-0777).
- Потоки — в разных зонах.
- Базу меняет максимум один поток (трекер и так не выдаёт вторую задачу с базой).
- Общие файлы проверок (матрица доступа, перепись, помощники экранных тестов, настройки тестов) не правит ни один поток. Задаче они нужны — она идёт одна, когда второй поток стоит.
- Пока файл проверки доступов не разрезан (T-0784), второй поток берёт только задачи без базы.

## Конец волны
**11. Все задачи слиты** в `wave/<N>`, вердикты по всем цепочкам есть. Подтяни `main` (п.10).

**Коммиты после вердикта цепочки** — починка прогона, находки тестировщика, доделки, подтягивание `main`: трогают проверки (тот же список, что в `task.md`, п.11) — вердикт проверяющего на них (`asterion/2-checks-in-pr.md`, коммиты от вердикта до сейчас) до PR в `main`. «Ослаблена» и правка — снова проверяющий. Без вердикта на последний коммит, трогавший проверки, PR в `main` не открываешь.

**12. Проверки — всегда, все три:**
- **Полный прогон по ветке волны**: `full.yml` с `ref=wave/<N>`, база, мутации и все экраны (как запускать и ждать — `asterion/8-evening.md`, «прогон»; по ветке он умеет с T-0778, п.3). Прогон долгий: запись вида «остановка», «ждём полный прогон», разбудит диспетчер. Красный — починка PR в ветку волны, прогон заново.
- **Тестировщик** — `dev-tester` на ветке волны: все сценарии приёмки блока, все роли. Лист проблем сортируешь как в `task.md`, п.12: ошибки волны — PR в ветку волны; спорные — Ерлану пачкой; вкус и тексты — Даниилу пачкой.
- **Сверка проверяющего** — `dev-checker`: по каждой задаче — сделано ли по зерну (`asterion/3-after-merge.md`), и приёмка блока (`asterion/4-acceptance.md`) на локальном стеке ветки волны. Доделка — PR в ветку волны, затем снова полный прогон по задетому.

**13. Один PR в `main`** из `wave/<N>`: «Волна N: <блок>», не черновиком; в описании — задачи волны по порядку, итог прогона (ссылкой), лист тестировщика (сколько найдено и исправлено), вердикты проверяющего, правки проверок по цепочкам. `scripts/stop-list.sh`: секреты и боевая база — «да» Ерлана; правки проверок — под вердиктами цепочек и коммитов после них (п.11). **CI по PR волны зелёный** — только тогда слияние. Способ — по `CLAUDE.md` репозитория (правила дописывает T-0778). После слияния «Готово» задачам ставит трекер (T-0778, п.2), стенд обновляется сам — проверь.

**14. Итог** — запись в журнал узла волны: что слито, прогон, тестировщик, расход (`dev_run` `action: totals` по узлу). Ерлану — строка в утренней сводке.
