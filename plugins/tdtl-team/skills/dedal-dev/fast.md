# Быстрый режим (D-0120 п.1, п.4)

Мелкие правки только кода и текстов, пачкой по зоне. Без зерна, без техпроекта, без проверяющего. PR сразу в `main`. Проверки — свои тесты и ревьюер. Границу держит не твоё мнение, а скрипт `scripts/fast-mode.mjs` в tradelab-app (что он считает «не быстрым» и чего не видит — `docs/guards.md`, раздел «Граница быстрого режима»).

Только tradelab-app: в трекере и плагине скрипта нет — там режим «задача».

## 1. Пачка
- Задачи в режиме «быстрый» одной зоны (`find_tasks`, `task_pack`) или строки «ошибка» из листа тестировщика. Без зоны не берёшь (основа, «Начало запуска»).
- Одна зона — одна ветка. Две зоны — две пачки, по очереди или двумя потоками (правила потоков — `wave.md`, «Параллельно»).
- Пачка небольшая: дифф, который ревьюер читает целиком. Задача с вопросом из списка «Что идёт Ерлану» в пачку не входит — она идёт в режим «задача».
- В журнал каждой задачи пачки: «Дедал: запуск начат — быстрый, ветка …».

## 2. Ветка
От свежего `main`: `claude/fast-<зона>-<коротко>`, зона и суть — латиницей (`claude/fast-chat-podpisi`). Префикс `claude/fast-` обязателен: по нему CI гоняет шаг «Граница быстрого режима».

## 3. Код — исполнитель
Агент `dev-executor`, модель sonnet (после двух возвратов ревьюера — opus). В промпте: номера задач пачки, путь к клону, ветка, «режим быстрый: без зерна, существующие тесты не меняешь, `specs/` не трогаешь».
- Источник — описание задачи (или строка листа тестировщика: шаг, роль, что случилось, как повторить).
- **Свои тесты.** Новые тесты можно — новыми файлами. Существующие тесты и их помощники не меняются: правка существующей проверки — уже не быстрый режим (скрипт так и ответит).
- Спеки, замка и `specs/T-…` нет: папка `specs/` — граница режима.

## 4. Проверки у себя
По `CLAUDE.md` репозитория (`/verify`): линт, типы, юнит-тесты, свои новые экранные тесты и смоук. Полный набор экранов не гоняешь. Что прогнал — в описание PR. Неустойчивый тест — как в `take-task/steps.md`, п.5, «Неустойчивый тест».

## 5. Граница
`node scripts/fast-mode.mjs` в клоне ветки.
- «быстрый можно» — дальше.
- «в режим «задача»» с файлами и причинами — остановись. Задачу, чья правка задела такой файл, переводишь: `set_dev` с `mode: задача` и причиной — строкой скрипта; её правки убираешь из ветки, дальше она идёт по `task.md` отдельно. Остальное пачки — снова скрипт. Не уверен, какой задаче принадлежит файл, — вся пачка в режим «задача».
- Скрипт не видит смысла правки: подпись кнопки может менять поведение для клиента. Это вопрос ревьюеру (п.6).

## 6. Ревьюер
Агент `reviewer`, модель opus, на дифф ветки против `main`. В промпте добавь: «режим быстрый — проверь ещё: меняет ли правка поведение для клиента, права или деньги; правит ли существующие тесты».
- Блокеры — исполнителю, снова скрипт и ревьюер. Ревьюер дважды вернул — исполнитель на opus; после третьего круга блокеры остались — остановка.
- «Меняет поведение для клиента» — задача уходит в режим «задача» (п.5) или, если правка про новое для клиента, — вопрос Ерлану (основа).
- Журнал каждой задачи пачки, одной записью после последнего круга: «Ревьюер: блокеры — …; исправлено — …; отложено — … (почему)». Ревьюер нашёл блокер, который не поймал ни один тест, — урок (как в `take-task/steps.md`, п.6) пишешь в ту же запись строкой «урок: …»: `specs/` в этой ветке не трогаешь, в `specs/LESSONS.md` его внесёт ближайший PR режима «задача» в этом репозитории.

## 7. PR и CI
- Подтяни `main`, снова п.4 и п.5, если что-то пришло. После ревьюера код молча не меняется: любая правка, кроме разрешения конфликта без смены смысла, — снова ревьюер.
- PR в `main`, сразу готовым, не черновиком. Название: номера всех задач пачки и зона — «T-0801 T-0802 Быстрые правки: чат» (трекер двигает статус по номерам в названии). Черновик снять — как в `take-task/steps.md`, п.7.
- Описание: что сделано по каждой задаче; что прогнал; ответ `fast-mode.mjs`; «режим быстрый: без зерна, без вердикта проверяющего».
- `scripts/stop-list.sh` после последнего подтягивания `main`: назвал файл — это уже не быстрый режим, п.5.
- Дождись CI. Красный — исполнителю в той же ветке; два круга не помогли — остановка.

## 8. Слияние
Сам, после ревьюера и зелёного CI, тем же порядком, что `take-task/steps.md`, п.10 (squash через `gh api`, «ветка отстала», среда не дала слить — остановка). Трекер сам поставит «Готово». Журнал каждой задачи: «Дедал: запуск закончен — PR …, что проверено». Вечернюю проверку не ждёшь: чужие экраны ловит она.
