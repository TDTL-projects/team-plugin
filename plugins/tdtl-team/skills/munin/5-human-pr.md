## 5. PR людей (D-0041)
PR, которые ведут не по навыку `take-task`: другой разработчик, правка по решению D-…, документ. Назвали PR — берёшь его, кроме репозиториев «вне линий»: про такой PR скажи, что его сливает владелец, и не проверяй; «что висит» или запуск по расписанию — открытые, не черновики, только в репозиториях линии ТД+XP из таблицы линий (DocsSystem; репозитории «вне линий» не смотрит никто), где после твоего последнего отзыва есть новые коммиты или комментарии. PR задачи, которую ведут по `take-task` (в журнале «Паровоз: запуск начат» новее последнего «запуск закончен»), не трогаешь; «НЕ СЛИВАТЬ» в описании — не трогаешь.

Проверка, по порядку:
1. В названии PR есть `T-…` или `D-…`, и изменения в их рамках. Нет номера — замечание, дальше не проверяешь.
2. PR — одна задача. Внутри три разные вещи — попроси разбить.
3. Агент `reviewer` на дифф ветки против `main`, с чистым контекстом; скажи ему, что за репозиторий и где код выполняется.
4. Проверки GitHub зелёные. CI нет — прогони тесты из PR сам, в отдельной папке, без секретов в окружении.
5. Секретов и данных клиентов нет ни в коде, ни в тестах, ни в описании.
6. Видимое на сайте — пройди шаги демо из описания на preview. Превью Vercel красное с причиной «автор не в команде Vercel» — не замечание: собери превью ветки через коннектор Vercel или опирайся на смоук из CI и напиши «вид на сайте проверит Наиль после слияния».
7. Правки проверок в PR — как в разделе 2: стала ли проверка слабее.

Сливаешь сам, если пункты 1–7 в порядке:
- документы и техпроекты волн;
- терминал и брокер (DocsSystem) — код, миграции и тестовые данные стенда.

Только по «да» Наиля (колонка «Секреты и боевая база» таблицы линий):
- секреты; рабочие базы DocsSystem — по её `CLAUDE.md`;
- архитектурные развилки: новый внешний сервис или API, платный сервис, удаление данных.

Итог:
- В порядке → отзыв с меткой и что проверил, слияние squash, журнал задачи: «Мунин: PR #N проверил и слил».
- Замечания (и красный CI тоже) → отзыв: по каждому — что не так, чем грозит, как поправить; журнал задачи: «Мунин: нужны правки в PR #N — коротко». Одни и те же замечания второй раз не пишешь: новая запись — после новых коммитов.
- Нужно «да» Наиля → отзыв «проверка пройдена, сливает Наиль» и ему одна-две фразы: что в PR, чем рискуем, твой совет, «да/нет?».
- Два круга не сошлись → вопрос Наилю Q-…. С третьего круга PR блокирует только то, что удаляет или затирает чужое: данные, файлы, работу людей; остальное — «можно отдельной задачей».
