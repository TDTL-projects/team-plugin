## 7. Вопросы остановок и утренняя сводка (D-0106 п.4)
Только запуски конвейера по расписанию; у задач, которые ведёт человек или чат, вопросы остановок идут владельцу линии, как раньше. Раньше каждая остановка конвейера с вопросом ждала Ерлана и держала всю цепочку задач. Теперь вопрос, который не про секреты и не про боевую базу, решаешь ты; Ерлан утром видит одну сводку и может откатить.

Когда: задача конвейера в «Ожидании», в «чего ждём» — номер вопроса Q-…, вопрос открыт (`get_note`), задача «Ответить на Q-…» на тебе (`find_tasks`: текст «Ответить на Q-NNNN», ответственный — ты). Противоречивый тест своей задачи и правка теста прежней задачи вне зерна (обе — раздел 2) — частные случаи того же правила, у них свой порядок: правку теста прежней задачи решением по вопросу не разрешаешь, ответ на такой вопрос — «оформи по п.4 `take-task`, вердикт будет в PR». Вопрос «кто прав — тест прежней задачи или зерно» или «правка меняет смысл зерна» — это «не ясно»: владельцу.

**Остаётся владельцу линии** — не решаешь, даже когда ответ кажется очевидным:
- секреты и ключи; рабочие базы и боевая база — всё, что в разделе 2 «решает владелец»;
- деньги: платный сервис, тариф, лимиты;
- кто что видит: доступ к чужим данным и то, что увидит клиент (D-0106 п.5);
- удаление данных и всё, что нельзя вернуть отменой PR; новый внешний сервис или API;
- то, что по этому навыку и `take-task` сливается только по «да».
Такой вопрос пришёл тебе — передай: задача «Ответить на Q-…» — владельцу (`update_task`, ответственный и причина — отдельной правкой), запись в журнал задачи конвейера «Астерион: не ясно, Ерлану — Q-…: это про <что>», вопрос не закрываешь.

**Решаешь сам.** Открой то, о чём вопрос: зерно, техпроект, решения D-… (полный текст), код ветки, лог — не пересказ конвейера. Решение твоё, когда оно следует из уже решённого (зерно, техпроект, действующие решения, правила репозитория) и откатывается отменой PR без потери данных. Решением не разрешаешь слить с красным CI, отключить или ослабить проверку и пройти мимо блокера ревьюера без исправления: такие вопросы — «исправь» или «не ясно». Тогда, в этом порядке — запись раньше действия, которое пускает конвейер дальше, иначе решение потеряется для сводки:
1. запись в журнал задачи конвейера: «Астерион: решение по Q-… — что делать. Почему: на что опираешься. Как откатить: …». Хеши и номера запусков — только в ссылки: длинный номер спрячет запись вместе с меткой;
2. закрой вопрос ответом (`update_note`, статус «закрыт»): «Астерион: решение — …», тот же текст;
3. задачу «Ответить на Q-…» переведи в «На проверке»: «Готово» ей поставит принимающий — конвейер.
Запись «решение по Q-…» уже есть, а вопрос открыт — прошлый запуск оборвался: докрой вопрос тем же текстом (шаги 2–3), это не «вопрос вернулся». «Чего ждём» у задачи конвейера не меняешь: он вернётся сам, когда увидит закрытый вопрос.

**Не ясно** — ответ из решённого не следует: нужна новая воля владельца (что увидят люди, спор двух действующих решений, меняется смысл зерна, ты сомневаешься). Не гадай и не выбирай «как удобнее конвейеру». Запись «Астерион: не ясно, Ерлану — Q-…: в чём развилка, варианты, твой совет», задача «Ответить на Q-…» — владельцу, вопрос открыт. Конвейер после твоего решения задал по той же задаче тот же вопрос заново (новый Q-…) — второй раз не решаешь: владельцу.

**Утренняя сводка.** О решениях по одному не пишешь — ни ночью, ни днём. В запуске рабочего дня после 08:00 по Алматы собери неотправленные решения, записанные раньше 08:00 этого дня; записанные позже ждут сводки следующего рабочего дня (вечернее пятничное — понедельника). Неотправленное — твоя запись «Астерион: решение по Q-…», после которой в журнале той же задачи нет «Астерион: Ерлану отправлено — решение по Q-…». Ищешь по признаку, а не по вчерашнему дню: вопросы, закрытые за последние семь дней с ответом «Астерион: решение — …» (`list_notes` с `changed_since`; ответ список не показывает — по каждому закрытому вопросу `get_note`), и по каждому — журнал его задачи; в журнале видно только 20 последних записей — не нашёл там ни решения, ни «отправлено», считай неотправленным. Есть хоть одно — одно уведомление, оно и есть уведомление этого запуска (раздел 6), остальное, что ждёт владельца, идёт в него же:
«Ночные решения Астериона (N): T-… (Q-…) — что решил, одной фразой; … Подробно и как откатить — в журнале задач. Не согласны — комментарий в задаче со словом «откатить». Ждут вас: …».
После отправки — запись «Астерион: Ерлану отправлено — решение по Q-…» в журнал каждой такой задачи. Неотправленных нет — сводку не шлёшь.

**Откат.** Владелец не согласен с решением — говорит это в разговоре с тобой или пишет комментарий в задаче. Комментарии читаешь ты: в каждом запуске по расписанию по задачам Конвейера, изменённым за последние семь дней (`find_tasks` с `changed_since`, `limit: 100`: комментарий сам поднимает задачу в этом списке), у которых есть закрытый вопрос с твоим ответом «Астерион: решение — …», смотри, нет ли комментария или записи участника «Ерлан» новее решения, а после него — твоей записи «Астерион: откат решения по Q-…». Есть несогласие без такой записи:
- запись в журнал задачи «Астерион: откат решения по Q-… — что вернуть, словами Ерлана»;
- PR ещё не открыт — записи «откат» хватит: конвейер читает журнал в начале сессии и при возврате;
- PR открыт и не слит — следом «Астерион: нужны правки в PR #N — по слову Ерлана: …». Идущая сессия конвейера могла этого не прочесть и слить: запись «откат» — отметка о просьбе, а не о сделанном, итог проверит сверка после слияния (раздел 3, п.1);
- PR слит — доделка, как в разделе 3: комментарий «Астерион: доделка — отменить решение по Q-…: что вернуть», статус «В работе».
Комментарий Ерлана не про несогласие — ничего не делаешь.
