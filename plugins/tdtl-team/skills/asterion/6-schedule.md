## 6. По расписанию
Запуск «Астерион» или «Мунин». Ключ трекера и репозитории — в инструкции запуска. Каждый видит только свою линию: в `find_tasks` Мунин всегда передаёт `project: P-08`, Астерион — `project: -P-08`. За один запуск, в этом порядке:
1. **Конвейер стоит и ждёт тебя**: `find_tasks`, ответственный — свой конвейер (участник «Конвейер» или «Паровоз»), статус «Ожидание», с `project` своей линии; по каждой `get_task` смотри «чего ждём». Это первым.
   - «вердикт Астериона по PR #N» / «вердикт Мунина по PR #N» — раздел 2.
   - «вердикт Астериона по зерну» / «вердикт Мунина по зерну» (зерно со строкой «Репозиторий» из строки «Вне линий» — не проверяешь, это задача владельца) — задачу поставили «К разработке» без твоей проверки: раздел 1, вердикт в журнал. В журнале «Конвейер: правка проверок вне зерна — …» (в ТД+XP — «Паровоз: …») новее твоего вердикта — старая остановка: раздел 1, «Правка проверок вне зерна».
   - «слить PR #N: среда не дала» — конвейер всё прошёл, но слить не смог. Запусти `scripts/stop-list.sh origin/main` на ветке: правок проверок, секретов и рабочих баз нет, CI зелёный — слей (squash) и запиши «PR #N слил Астерион: конвейеру среда не дала». Есть правки проверок — раздел 2. Тебе тоже не дали — в уведомление владельцу линии: «PR #N готов и проверен, слить кнопкой: <ссылка>».
   - «снять черновик с PR #N» — сними отметку (`gh api -X POST repos/<владелец>/<репо>/pulls/<N>/ccr/ready_for_review`). Не вышло — в уведомление владельцу линии: «открыть PR #N и нажать Ready for review: <ссылка>».
   - «слить техпроект: <файл>» — задачи волны стоят, потому что техпроекта нет в `main`. Проверь техпроект (раздел 1) и слей PR после «техпроект проверен». Техпроект «не готов» или PR нет — в уведомление владельцу линии: «волна стоит: техпроект ждёт Дедала» (в ТД+XP — Хугина).
   - номер вопроса Q-…, вопрос открыт, и задача «Ответить на Q-…» на тебе (линия TradeLab) — раздел 7. Там же, в каждом запуске: несогласие владельца с твоим решением («Откат»).
   - «зелёный полный прогон» — конвейер вернётся к задаче сам, когда отметка позеленеет. Твоё здесь — чтобы она могла позеленеть: разбор красного прогона и «Прогон после починки» (раздел 3).
   - «да Ерлана на слияние» / «да Наиля на слияние» — раздел 2, последний пункт: если в PR есть и правки проверок, сначала вердикт по ним, потом ответ владельцу линии.
2. **Техпроекты**: открытые PR «… Техпроект волны N» в репозиториях продукта своей линии без твоего вердикта для последнего коммита — раздел 1, сначала они.
3. **Зёрна**: `find_tasks`, статус «Предложена», по каждому направлению отдельно, `limit: 100`, с `project` своей линии (Мунин — `project: P-08`, Астерион — `project: -P-08`); зерно со строкой «Репозиторий» из строки «Вне линий» не проверяет никто; вид «Разработка», зерно отмечено готовым, в журнале нет твоего вердикта для текущей версии. Раздел 1. Задачи с одним техпроектом проверяй вместе, как пачку. Вердикт для той же версии переписываешь в двух случаях: «не готово» было из-за открытого вопроса, а вопрос с тех пор закрыт; и перепроверка задетых зёрен по PR правки техпроекта (раздел 1).
4. **Приёмка**: задачи «Приёмка: …» на тебе — «Предложена», когда все зависимости «Готово» или «Отменена»; «В работе» без итоговой записи «Астерион: приёмка — …» (прошлый запуск оборвался); «Ожидание», когда все задачи из «чего ждём» снова «Готово». Раздел 4.
5. **Сверка после слияния** — раздел 3, вместе с ней **полный прогон по `main`**: красная отметка — раздел 3, «Полный прогон красный»: разбор, а если он уже есть — «Прогон после починки». **PR людей** — раздел 5.
6. **Что ждёт владельца линии**: задачи своего конвейера в «Ожидании» с «да Ерлана на слияние» (в ТД+XP — «да Наиля на слияние») или открытым вопросом к нему; зёрна и техпроекты, которые не готовы и ждут Архонта или техлида линии (нет раздела «Для разработки», открытый вопрос, техпроект «не готов»).

Владельцу линии — одно уведомление за запуск; получатель и инструмент — по таблице линий: в TradeLab Ерлану push-уведомление (инструмент `PushNotification`), в ТД+XP Наилю сообщение (`send_message`, `weekend` не ставишь). Решения по вопросам остановок (раздел 7) идут только в утренней сводке. Только когда есть что сказать: что ждёт его «да» (с твоим советом), итог приёмки, что вернул на доделку, какой техпроект проверен (можно писать зёрна) или не готов, какие зёрна готовы и какие стоят и чего ждут. Об одном и том же ожидании пишешь один раз: отправил — оставь в журнале задачи «Астерион: Ерлану отправлено — …» (в ТД+XP — «Мунин: Наилю отправлено — …»); есть такая запись новее причины ожидания — не повторяй. В выходные уведомлений не шлёшь: что накопилось, уйдёт в первом запуске понедельника. Нечего делать — закончи одной строкой.
