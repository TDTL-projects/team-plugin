## 8. Вечерняя проверка (T-0711)
Только в запуске «Вечерняя проверка» (22:00 по Алматы, каждый день). В обычном запуске этот раздел не читаешь. Репозиторий — tradelab-app; CI на PR лёгкий, полный прогон идёт только кнопкой (`CLAUDE.md` и `docs/guards.md` репозитория). Журнал решений — задача-узел T-0712 «Вечерние проверки TradeLab — журнал решений» (SP-31). Других дел в этом запуске нет: разделы 1–7 не открываешь, кроме раздела 3 при красном прогоне.

1. **Что слито.** Прошлая проверка — последняя твоя запись «Астерион: вечерняя проверка …» в журнале T-0712, в ней коммит `main`; записи нет — коммит `main` 24 часа назад. В клоне свежего `main`: `node scripts/e2e-select.mjs --evening --base <коммит прошлой проверки> --head origin/main` — слитые коммиты, задачи, поводы и предложение частей. Ничего не слито — запись «Астерион: вечерняя проверка не нужна — main <хеш>: ничего не слито», конец.
2. **Нужна ли.** Поводы: миграции, правила доступа (RLS) и тесты базы, общие таблицы, данные стенда, общие файлы тестов (помощники `e2e/`, `playwright.config.ts`), `package.json` и lock-файл, настройки сборки (`tsconfig.json`, `next.config.ts` и др.), CI, общие компоненты экранов, удалённые экранные тесты, и «полный набор: причина» в описаниях слитых PR (так исполнитель называет то, что не прогнал у себя, — `take-task`, п.5). Нет ни одного повода и ни одной задачи с экранами — не нужна. Предложение скрипта — подсказка, решаешь ты: не уверен, что повод безвреден, — нужна.
   - **Части.** База и мутации — если задевали базу (миграции, политики, тесты базы, данные стенда, запуск стека, файл типов). Экраны — только задетые за день: свои e2e слитых задач и их `e2e-also.txt` (их даёт скрипт), плюс чужие экраны, которые используют изменённые общие компоненты (`grep` по имени компонента в `src/app/`, экран → его `e2e/T-…spec.ts`). «все» — при правке `package.json`, `playwright.config.ts`, общих помощников `e2e/`, настроек сборки или CI.
   - **Красное не гасится частью.** Последняя отметка «Полный прогон» на `main` красная (как читать — `take-task`, «Как читать отметку») — в сегодняшний прогон входят и части того красного запуска (видны в итоге его шага «Что гоняем»; не видно — все), даже если сегодня их не задевали: иначе зелёный прогон одних экранов снимет красное с базы.
3. **Не нужна** — запись в журнал T-0712 «Астерион: вечерняя проверка не нужна — main <6 знаков хеша>: почему» и конец.
4. **Нужна:**
   - пауза: `dev_pause` (коннектор трекера) сначала `action: status`. Стоит пауза с причиной «вечерняя проверка …» от Астериона — её поставил прошлый запуск, продолжай с ней. Стоит чужая (админ, другая причина) — не трогаешь и в конце не снимаешь, прогон всё равно запускаешь. Не стоит — `action: on`, причина «вечерняя проверка main <хеш>». Не дали поставить — запись «нужна, но паузу не поставить: …», прогон всё равно запускаешь;
   - запись «Астерион: вечерняя проверка нужна — main <хеш>: части <база, мутации, экраны: N файлов>; почему: …»;
   - прогон: `gh api -X POST repos/TDTL-projects/tradelab-app/actions/workflows/full.yml/dispatches -f ref=main -f "inputs[db]=true|false" -f "inputs[mutations]=true|false" -f "inputs[e2e]=<файлы через пробел | все | пусто>"`; номер запуска — из `.../actions/workflows/full.yml/runs?branch=main&event=workflow_dispatch&per_page=1`. Не дали запустить — снять свою паузу (`action: off`), запись «вечерняя проверка красная — не запустить прогон: …»;
   - жди итога, не заканчивая запуск: статус запуска раз в 2–3 минуты (фоновой командой или Monitor — короткие ожидания в основном окне среда запрещает). Предел — 85 минут от постановки паузы (на 90-й трекер снимет её сам).
5. **Зелёный** — `dev_pause` `action: off` (только свою), запись «Астерион: вечерняя проверка зелёная — main <хеш>, <минуты прогона>», ссылка на запуск — в ссылках записи (длинный номер в тексте спрячет сторож). После снятия Конвейер запустит диспетчер трекера, сам не запускаешь.
6. **Красный** — разбор по разделу 3, «Полный прогон красный», пп. 1–5, в этом же запуске (не в следующем): первая попытка — перезапуск упавших задач и снова ждёшь в пределах 85 минут; вторая попытка — среда (п.2) или виновник (пп. 3–4, доделка). Отличие одно: в п.5 вместо уведомления владельцу — новая задача на починку (навык `new-task`: проект и подпроект виновника или SP-31, в описании — что упало; ссылка на запуск — в ссылках записи; зерно не пишешь); запись «Астерион: полный прогон красный — …» в журнал последнего кандидата — как там.
   - **Критично ли**: ломает вход, данные, права или экран, которым пользуются, либо мешает задачам в очереди (тот же экран, та же таблица). Доделка и так идёт у Конвейера первой (`take-task`, «Запуск по расписанию»); критичность — только для сводки. Новая задача без зерна в очередь Конвейера не попадёт, пока Архонт не напишет зерно и админ не поставит «К разработке»: критично — `set_priority` «Сейчас» с причиной и в сводке «ждёт зерна и «К разработке»: T-…»; нет — «Потом».
   - `dev_pause` `action: off` (только свою), запись «Астерион: вечерняя проверка красная — main <хеш>: что упало; T-… — доделка | новая задача | среда; критично | не критично», ссылка на запуск — в ссылках записи.
7. **Не закончилась за 85 минут** — `dev_pause` `action: off` (только свою), запись «Астерион: вечерняя проверка не закончилась за 85 минут — main <хеш>, запуск идёт», ссылка — в ссылках записи. Итог прогона разберёт обычный запуск (раздел 3).

Пока стоит твоя пауза или в журнале T-0712 есть запись «вечерняя проверка нужна» без итога, обычный запуск Астериона этот прогон не трогает (раздел 3). Ерлану в этом запуске не пишешь: всё — строкой утренней сводки (раздел 7). Данных клиентов в записях нет.
