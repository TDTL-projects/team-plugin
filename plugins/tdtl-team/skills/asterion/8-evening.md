## 8. Вечерняя проверка (T-0711)
Только в запуске «Вечерняя проверка» (22:00 по Алматы, каждый день). В обычном запуске этот раздел не читаешь. Репозиторий — tradelab-app; CI на PR лёгкий, полный прогон идёт только кнопкой (`CLAUDE.md` и `docs/guards.md` репозитория). Журнал решений — задача-узел «Вечерние проверки TradeLab — журнал решений» (SP-31; найти — `find_tasks` по названию). Других дел в этом запуске нет: разделы 1–7 не открываешь, кроме раздела 3 при красном прогоне.

1. **Что слито.** Прошлая проверка — последняя твоя запись «Астерион: вечерняя проверка …» в журнале узла, в ней коммит `main`; записи нет — коммит `main` 24 часа назад. В клоне свежего `main`: `node scripts/e2e-select.mjs --evening --base <коммит прошлой проверки> --head origin/main` — слитые коммиты, задачи, поводы и предложение частей. Ничего не слито — запись «не нужна — ничего не слито», конец.
2. **Нужна ли.** Поводы: миграции, правила доступа (RLS) и тесты базы, общие таблицы, общие файлы тестов (помощники `e2e/`, `playwright.config.ts`), `package.json` и lock-файл, CI, общие компоненты экранов. Нет ни одного повода и ни одной задачи с экранами — не нужна. Предложение скрипта — подсказка, решаешь ты: не уверен, что повод безвреден, — нужна.
   - **Части.** База и мутации — если задевали базу (миграции, политики, тесты базы, запуск стека). Экраны — только задетые за день: свои e2e слитых задач и их `e2e-also.txt` (их даёт скрипт), плюс чужие экраны, которые используют изменённые общие компоненты (`grep` по имени компонента в `src/app/`, экран → его `e2e/T-…spec.ts`). «все» — только при правке `package.json`, `playwright.config.ts`, общих помощников `e2e/` или CI.
3. **Не нужна** — запись в журнал узла «Астерион: вечерняя проверка не нужна — main <6 знаков хеша>: почему» и конец.
4. **Нужна:**
   - пауза: `dev_pause` (коннектор трекера), `action: on`, причина «вечерняя проверка main <хеш>». Отказ «пауза уже стоит» — её поставил прошлый запуск, продолжай с ней. Не дали поставить — запись «нужна, но паузу не поставить: …», прогон всё равно запускаешь;
   - запись «Астерион: вечерняя проверка нужна — main <хеш>: части <база, мутации, экраны: N файлов>; почему: …»;
   - прогон: `gh api -X POST repos/TDTL-projects/tradelab-app/actions/workflows/full.yml/dispatches -f ref=main -f "inputs[db]=true|false" -f "inputs[mutations]=true|false" -f "inputs[e2e]=<файлы через пробел | все | пусто>"`; номер запуска — из `.../actions/workflows/full.yml/runs?branch=main&event=workflow_dispatch&per_page=1`. Не дали запустить — снять паузу (`action: off`), запись «вечерняя проверка красная — не запустить прогон: …», строка в сводку;
   - жди итога, не заканчивая запуск: статус запуска раз в 2–3 минуты (фоновой командой или Monitor — короткие ожидания в основном окне среда запрещает). Предел — 85 минут от постановки паузы.
5. **Зелёный** — `dev_pause` `action: off`, запись «Астерион: вечерняя проверка зелёная — main <хеш>, <минуты прогона>», ссылка на запуск — в ссылках записи (длинный номер в тексте спрячет сторож). После снятия Конвейер запустит диспетчер трекера, сам не запускаешь.
6. **Красный:**
   - первая попытка — один перезапуск упавших задач (`.../actions/runs/<номер>/rerun-failed-jobs`): чаще это среда (образ не скачался, сбой GitHub). Снова ждёшь;
   - снова красный — разбор по разделу 3, «Полный прогон красный», пп. 3–5: кандидаты — слитые с прошлой проверки, виновник — по диффу против упавшего теста. Виновник — задача конвейера: доделка (раздел 3, п.4). Не задача конвейера или виновника нет — новая задача на починку (навык `new-task`, проект и подпроект виновника или SP-31, в описании — что упало и ссылка на запуск; зерно не пишешь);
   - **критично ли**: ломает вход, данные, права или экран, которым пользуются, либо мешает задачам в очереди (тот же экран, та же таблица) — критично: `set_priority` «Сейчас» с причиной, задача первой в очереди Конвейера (доделки и так идут первыми, `take-task`). Нет — «Потом», в конец очереди;
   - `dev_pause` `action: off`, запись «Астерион: вечерняя проверка красная — main <хеш>: что упало; T-… — доделка | новая задача; критично (первой в очередь) | не критично (в конец)».
7. **Не закончилась за 85 минут** — `dev_pause` `action: off` (через 90 минут трекер снимет паузу сам), запись «Астерион: вечерняя проверка не закончилась за 90 минут — main <хеш>, запуск идёт: …». Итог прогона разберёт сверка после слияния в обычном запуске (раздел 3, «Полный прогон красный»).

Ерлану в этом запуске не пишешь: всё — строкой утренней сводки (раздел 7). Данных клиентов в записях нет.
