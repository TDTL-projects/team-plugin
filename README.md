# Ариадна — плагин команды TDTL

Навыки Claude для работы команды автоматизации с трекером. Помощников двое (решение D-0016):

- **Ариадна** — порядок и журналы: «Ариадна, запиши», «Ариадна, заведи задачу», «Ариадна, выложи на Диск», «Ариадна, наведи порядок в TD».
- **Архонт** — менеджер проекта: «Архонт, мои задачи», «Архонт, что дальше по P-01», «Архонт, разложи T-…».

Обычные фразы без имени тоже работают; перепутанное имя не мешает — навык выбирается по делу.

| Навык | Кто | Что делает |
|---|---|---|
| `how-we-work` | оба | кто за что отвечает, где что лежит, направления, статусы, кто ведёт и кто принимает, рабочая папка, правила |
| `log-work` | Ариадна | запись в журнал задачи; «На проверке» — с принимающим |
| `new-task` | Ариадна | новая задача с принимающим, передача задачи, решение или вопрос; при записи решения спрашивает «заменяет или уточняет прежнее?» (D-0049); гипотеза — задача-исследование с шестью строками (D-0052) |
| `publish-to-drive` | Ариадна | выложить готовый файл из рабочей папки на общий Диск в подпапку подпроекта, сразу привязать к задаче и записать ссылку в журнал |
| `tidy-drive` | Ариадна | навести порядок в папке направления на Диске: номер задачи в названии, подпапки подпроектов, привязка к задаче, старое — в «Референс», дубли; только по «да» |
| `bpmn-to-figma` | Ариадна | копия схемы процесса из `.bpmn` в FigJam (через коннектор, с обновлением на месте) или SVG для Figma Design — скриптом по координатам файла |
| `bpmn-merge` | Ариадна | свести копии одной схемы `.bpmn` от разных авторов: новое — само, правки и удаления — на решение владельцу |
| `my-tasks` | Архонт | мои задачи, что горит, что жду принять, советы Архонта, что брать дальше; напоминание о лимитах фокуса (D-0051) |
| `pm` | Архонт | что дальше по проекту (что можно начинать и что держит), разложить задачу или работу, зерно на разработку, «готово к разработке?»; напоминания о лимитах фокуса и о размере задачи (D-0051) |
| `dedal` | Дедал | до разработки: готова ли задача к «К разработке» — чеклист, раздел «Для разработки» в зерне, дубли и пересечения; по расписанию — вердикт в журнал задачи (D-0054) |
| `take-task` | конвейер: запуск по расписанию, человек в Claude Code, агент в чате | задача из «К разработке» до слияния: спека и тесты до кода (агент `spec-tests`) → код → проверки → ревьюер → PR → CI → демо → слияние; метки «Конвейер: запуск начат / закончен» в журнале; стоп-список — по «да» Ерлана |
| `review-pr` | Дедал | после разработки: проверить чужой PR и слить самому; сверка после слияния, доделка — той же задачей; скрипты плагина с сетью или удалением файлов, база и функции трекера, правки проверок, секреты и архитектурные развилки — только по «да» Ерлана (D-0041) |

Боты трекера по расписанию подписаны так же: опись Диска и сводки журналов — «Ариадна», советы в трекере и утреннее сообщение в общий чат — «Архонт».

Агенты (Claude Code и Cowork): `spec-tests` (до 0.14 — `dedal`) — шаг конвейера: спека и приёмочные тесты из зерна, замок на тесты; `reviewer` — проверка изменений, замка тестов и рамок задачи.

Установка в Claude Code:

```
/plugin marketplace add TDTL-projects/team-plugin
/plugin install tdtl-team@tdtl
```

`tdtl` — имя маркетплейса из `.claude-plugin/marketplace.json`.

В приложении Claude: «Персонализация» → «Плагины» → «+ Добавить» → «Добавить маркетплейс» → `TDTL-projects/team-plugin`.

Навыкам нужен коннектор «Трекер», навыку `publish-to-drive` — ещё коннектор Google Drive. Как всё устроено и как подключить — страница [«Как мы работаем»](https://tl-pm-demo-puce.vercel.app/guide) на сайте трекера (пункт в меню сайта), раздел «Настройка за 20 минут».

Правки навыков — через PR в этот репозиторий; при каждой правке поднимать `version` в `plugins/tdtl-team/.claude-plugin/plugin.json`. После слияния плагин обновится у всех, у кого включена синхронизация маркетплейса.
