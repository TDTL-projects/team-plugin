# Ариадна — плагин команды TDTL

Навыки Claude для работы команды автоматизации с трекером. Помощников для всех двое (решение D-0016):

- **Ариадна** — порядок и журналы: «Ариадна, запиши», «Ариадна, заведи задачу», «Ариадна, выложи на Диск», «Ариадна, наведи порядок в TD».
- **Архонт** — менеджер проекта: «Архонт, мои задачи», «Архонт, что дальше по P-01», «Архонт, разложи T-…».

Обычные фразы без имени тоже работают; перепутанное имя не мешает — навык выбирается по делу.

Для разработки — ещё трое (решение D-0088): **Дедал** — как делаем (техпроект, порядок), **Конвейер** — делает, **Астерион** — проверяет чужое в отдельной сессии. Вторая линия разработки — ТД+XP (P-08, DocsSystem): **Хугин**, **Паровоз**, **Мунин**, все «да» — Наиль; таблица линий — в навыке `take-task` (T-0350).

| Навык | Кто | Что делает |
|---|---|---|
| `how-we-work` | оба | кто за что отвечает, где что лежит, направления, статусы, кто ведёт и кто принимает, рабочая папка, правила |
| `log-work` | Ариадна | запись в журнал задачи; «На проверке» — с принимающим |
| `new-task` | Ариадна | новая задача с принимающим, передача задачи, решение или вопрос; при записи решения спрашивает «заменяет или уточняет прежнее?» (D-0049); гипотеза — задача-исследование с шестью строками (D-0052); большую задачу предлагает завести главной с шагами-частями (D-0055) |
| `publish-to-drive` | Ариадна | выложить готовый файл из рабочей папки на общий Диск в подпапку подпроекта, сразу привязать к задаче и записать ссылку в журнал |
| `tidy-drive` | Ариадна | навести порядок в папке направления на Диске: номер задачи в названии, подпапки подпроектов, привязка к задаче, старое — в «Референс», дубли; только по «да» |
| `bpmn-to-figma` | Ариадна | копия схемы процесса из `.bpmn` в FigJam (через коннектор, с обновлением на месте) или SVG для Figma Design — скриптом по координатам файла |
| `bpmn-merge` | Ариадна | свести копии одной схемы `.bpmn` от разных авторов: новое — само, правки и удаления — на решение владельцу |
| `my-tasks` | Архонт | мои задачи, что горит, что жду принять, советы Архонта, что брать дальше; напоминание о лимитах фокуса (D-0051) |
| `pm` | Архонт | что дальше по проекту (что можно начинать и что держит), разложить задачу людей на шаги-части до взятия в работу (D-0055) или работу на задачи, зерно на разработку; напоминания о лимитах фокуса и о размере задачи (D-0051, D-0055) |
| `wave` | Архонт | подготовить волну разработки: свести документы и края сценариев, вопросы владельцу линии одной пачкой, техпроект от Дедала и его проверка, зёрна с самопроверкой, приёмка блока, пачка проверяющему линии, одна сводка владельцу линии на «да» (D-0088, D-0091) |
| `conductor` | дирижёр (только линия TradeLab: «Дирижёр, готовь волну N») | ведёт подготовку волны по навыку `wave`: запускает Архонта, Дедала и Астериона отдельными субагентами и сам передаёт ход; сам не пишет и не проверяет, состояние — в трекере (D-0106, T-0367) |
| `dedal` | Дедал (в ТД+XP — Хугин: «Хугин, …») | до разработки: техпроект волны (кто что заводит и кто чем пользуется, роль × действие, что покраснеет, общие файлы, порядок, приёмка), карта сторожей и уроки волн, раздел «Для разработки» в зерне, связи, дубли и пересечения (D-0088, D-0091) |
| `take-task` | конвейер (Конвейер или Паровоз: «Паровоз, возьми T-…»): запуск по расписанию, человек в Claude Code, агент в чате | задача из «К разработке» до слияния: спека и тесты до кода (агент `spec-tests`) → код → проверки → ревьюер → PR (не черновик) → CI → слияние; задачи строго подряд; метки «Конвейер: запуск начат / закончен» в журнале; правки проверок — по вердикту Астериона, секреты и рабочие базы — по «да» владельца линии; таблица линий TradeLab и ТД+XP |
| `asterion` | Астерион (в ТД+XP — Мунин: «Мунин, проверь …») | контроль в отдельной сессии: техпроект волны до зёрен, зёрна перед «К разработке» (замечания «держит» и «к сведению»), правки проверок в PR («стала ли проверка слабее»), сверка после слияния, приёмка блока по сценариям, PR людей; по расписанию — сводка владельцу линии (D-0088; до 0.15 проверку PR делал навык `review-pr`) |

Боты трекера по расписанию подписаны так же: опись Диска и сводки журналов — «Ариадна», советы в трекере и утреннее сообщение в общий чат — «Архонт».

Агенты (Claude Code и Cowork): `spec-tests` — шаг конвейера: спека и приёмочные тесты из зерна и техпроекта, замок на тесты задачи; `reviewer` — проверка изменений, замка тестов, рамок задачи и правок проверок.

Установка в Claude Code:

```
/plugin marketplace add TDTL-projects/team-plugin
/plugin install tdtl-team@tdtl
```

`tdtl` — имя маркетплейса из `.claude-plugin/marketplace.json`.

В приложении Claude: «Персонализация» → «Плагины» → «+ Добавить» → «Добавить маркетплейс» → `TDTL-projects/team-plugin`.

Навыкам нужен коннектор «Трекер», навыку `publish-to-drive` — ещё коннектор Google Drive. Как всё устроено и как подключить — страница [«Как мы работаем»](https://tl-pm-demo-puce.vercel.app/guide) на сайте трекера (пункт в меню сайта), раздел «Настройка за 20 минут».

Правки навыков — через PR в этот репозиторий; при каждой правке поднимать `version` в `plugins/tdtl-team/.claude-plugin/plugin.json`. После слияния плагин обновится у всех, у кого включена синхронизация маркетплейса.
